# Healthcare Security Compliance Assessment

I built this project to practice the security assurance side of cybersecurity: checking whether a control works, recording evidence, and deciding what should be fixed first.

The setting is **Northstar Community Clinic**, a fictional healthcare organization. I wrote a small Python model with doctor, nurse, patient, and administrator accounts and a sample patient record. The patient information is fake. This is **not** my earlier Flask medical-record application, a real hospital audit, or proof of HIPAA compliance.

## What I checked

I mapped 12 selected control objectives to NIST SP 800-53, HIPAA Security Rule safeguards, and related ISO 27001 control themes.

| Result | Controls |
| --- | ---: |
| Pass (within the small demo) | 5 |
| Gap | 2 |
| Not assessed | 5 |

The two open issues are an administrator test account with MFA disabled and audit events that disappear when the program stops. Neither is fixed in this version. The purpose is to show how findings can be supported with test results and tracked in a risk register.

## Run it

You'll need Python 3.10 or newer. No third-party packages are required.

```bash
python -m unittest discover -s tests -v
python -m src.assess
```

The first command runs **15 tests**. The second writes a fresh `evidence/assessment_results.json` file; its timestamps will change each run. Passing unit tests mean the checks behave as expected, **not** that every security control passes.

## How I approached the assessment

I chose a small set of controls that I could actually observe in a local program. For each one I wrote down the expected behavior, ran a test or reviewed the design, recorded the evidence, and gave it a result of PASS, GAP, or NOT ASSESSED.

The framework references are **illustrative mappings**, not an official crosswalk or certification. I did not include PCI DSS because the sample system does not process card payments. I did not use SAP GRC.

## Limits

There is no live login system, real MFA challenge, web server, cloud environment, encryption setup, or production logging. The risk scores are estimates for a fictional case. Five controls were not assessed because the model has no evidence for them. A production assessment would need a much wider scope and independent review.

I kept real company information, credentials, and patient data out of this repository.
